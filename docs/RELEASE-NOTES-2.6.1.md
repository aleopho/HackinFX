# HackinFX 2.6.1 / Android Remote 1.1.0

- Adds debounced passive USB topology observation and automatic native USB adapter refresh. Compatible new native devices join the running scene, removed devices leave it, existing deselections remain. The shared clock is retained. GPU setup and RAM detection are not rerun for USB events. OpenRGB devices are refreshed from the engine device list; hotplug detection still depends on the upstream controller implementation.
- Adds six MAKR 75 dial-ring LEDs at the upstream-defined offsets, exposing 87 mapped LEDs. Host media handling listens only on the exact MAKR vendor collection of interface 2 while HackinFX controls it. Documented clockwise/counterclockwise reports adjust a software-controllable default audio output through CoreAudio. Fixed-volume digital outputs cannot be adjusted this way. The listener never changes keyboard mappings or firmware. Physical verification is required.
- RAM profiles use normalized physical identity rather than volatile speed metadata, with schema-1 migration and a persistent reason when authorization is revoked. The two previously physically tested Titanium SKUs CMP32GX5M2B6000Z30 and CMP32GX5M2X7200C34 on the exact 8086:7f23 host may perform one bounded RGB-only identity probe to recreate a missing legacy profile. Unknown SKUs or previous revocation markers do not get automatic probing. Known RGB identities, CRC, protocol, LED count and DIMM count must match before lighting. Bus errors still stop control and require explicit manual validation. No SPD, memory timing or voltage access added.
- Android Remote replaces the legacy capture-intent path with an explicit camera activity and permission lifecycle. Adds full pairing-details paste, visible pairing errors, private credential-free crash traces, animated effect gallery cards, transitions and haptic selection.

Android and native builds are locally tested. Real phone camera/pairing, MAKR dial events, automatic RAM restart and physical hotplug must still be verified. The old widget practical validation remains outstanding. No EFI changes are part of this update.
